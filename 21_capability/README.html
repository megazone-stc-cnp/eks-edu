AWS EKS Capability 가이드

개요

AWS EKS Capability는 Amazon EKS 클러스터에서 관리형 애드온과 서비스를 쉽게 배포하고 관리할 수 있는 기능입니다. 이 가이드에서는 ArgoCD Capability를 중심으로 설정 방법과 사용법을 설명합니다.

AWS EKS Capability란?

AWS EKS Capability는 다음과 같은 특징을 가집니다:

  • 관리형 서비스: AWS에서 완전히 관리하는 서비스로, 설치, 업그레이드, 패치 등을 자동으로 처리

  • 통합 보안: AWS IAM 및 Identity Center와 완전히 통합된 보안 모델

  • 간편한 배포: 복잡한 설정 없이 몇 개의 명령어로 배포 가능

  • 고가용성: AWS의 인프라를 활용한 고가용성 보장

지원되는 Capability 유형

현재 지원되는 주요 Capability 유형:

  • ArgoCD: GitOps 기반 지속적 배포 도구

  • Flux: 또 다른 GitOps 도구 (향후 지원 예정)

  • 기타 관리형 서비스들 (지속적으로 추가 예정)

전체 실행 순서

ArgoCD Capability를 설정하고 사용하기 위한 전체 실행 순서는 다음과 같습니다:

# 1단계: ArgoCD Capability 생성
cd 21_capability/01_argocd

  ./02_create_role.sh          # IAM 역할 및 EKS Access Entry 생성
  ./03_create_argocd_capability.sh  # ArgoCD Capability 생성
  ./04_check_capability.sh     # Capability 상태 확인

# 2단계: Github Repository 등록
cd ../02_register_argocd
./01_create_secret_manager.sh    # Github에 등록 정보를 Secretmanager로 등록
./02_create_secret.sh            # Secret Manager에 대한 Secret 생성

# 3단계: Cluster 등록
cd ../03_register_cluster
./01_register_cluster.sh         # Secret에 Argocd의 Cluster 등록
./02_check.sh                    # 생성된 Secret 항목 체크

ArgoCD Capability 설정 가이드 스크립트별 상세 설명

각 스크립트의 주요 기능과 개선사항:

사전 요구사항

다음 사항들이 미리 준비되어야 합니다:

  • EKS 클러스터가 생성되어 있어야 함

  • AWS Identity Center (SSO) 설정이 완료되어 있어야 함

  • 적절한 IAM 권한을 가진 AWS 계정

  • env.sh 파일이 올바르게 설정되어 있어야 함

1단계: ArgoCD Capability 생성

1.1 IAM 정책 생성

ArgoCD Capability가 사용할 IAM Trust Policy를 생성합니다.

cd 21_capability/01_argocd
./01_make_policy.sh

이 스크립트는 다음 작업을 수행합니다:

  • tmp/argocd-trust-policy.json 파일 생성

  • EKS Capability 서비스가 역할을 assume할 수 있도록 허용하는 정책 정의

1.2 IAM 역할 및 EKS Access Entry 생성

ArgoCD Capability에서 사용할 IAM 역할과 EKS Access Entry를 생성합니다.

./02_create_role.sh

이 스크립트는 다음 작업을 수행합니다:

  • IAM 역할 생성: eks-edu-argocd-capability-role-${IDE_NAME}

  • IAM 정책 연결: AWSSecretsManagerClientReadOnlyAccess 정책 연결

  • EKS Access Entry 생성: IAM 역할을 EKS 클러스터에 등록

  • EKS Access Policy 연결:

    • AmazonEKSClusterAdminPolicy - 클러스터 관리자 권한

    • AmazonEKSArgoCDPolicy - ArgoCD 전용 권한

중복 실행 방지: 스크립트는 각 리소스의 존재 여부를 확인하여 이미 생성된 경우 건너뜁니다.

1.3 ArgoCD Capability 생성

실제 ArgoCD Capability를 EKS 클러스터에 생성합니다.

./03_create_argocd_capability.sh

이 스크립트는 다음 작업을 수행합니다:

  • AWS Identity Center 인스턴스 ARN 조회

  • 사용자 ID 조회 (RBAC 매핑용)

  • ArgoCD Capability 생성 및 RBAC 설정

주요 설정 항목:

  • Capability 이름: argocd-${IDE_NAME}

  • 타입: ARGOCD

  • RBAC 매핑: Identity Center 사용자를 ADMIN 역할로 매핑

  • 삭제 정책: RETAIN (Capability 삭제 시 ArgoCD 리소스 유지)

1.4 Capability 상태 확인

생성된 Capability의 상태를 확인합니다.

./04_check_capability.sh

예상 출력: ACTIVE (정상 생성 완료)

2단계: ArgoCD 클러스터 등록 및 애플리케이션 배포

2.1 ArgoCD CLI 설치 확인

ArgoCD CLI가 설치되어 있는지 확인합니다.

cd ../02_register_argocd
./00_is_install_argocd.sh

2.2 클러스터 등록

ArgoCD에 EKS 클러스터를 등록합니다.

./01_register_cluster.sh

이 스크립트는 다음 작업을 수행합니다:

  • ArgoCD 서버 엔드포인트 조회: EKS Capability에서 ArgoCD 서버 URL 자동 추출

  • ArgoCD 로그인: SSO를 통한 자동 로그인 시도

  • 클러스터 ARN 조회: EKS 클러스터의 ARN 정보 획득

  • 클러스터 등록: ArgoCD CLI를 사용하여 클러스터를 `in-cluster`라는 이름으로 등록

주요 개선사항: * AWS 프로필 설정에 따른 조건부 명령어 실행 * ArgoCD 서버 엔드포인트 자동 감지 * 중복 등록 방지 로직 * 로그인 실패 시 대안 방법 제공

2.3 샘플 애플리케이션 배포

ArgoCD를 통해 샘플 애플리케이션을 배포합니다.

./51_deploy_application.sh

배포되는 애플리케이션:

  • 이름: guestbook

  • 소스: https://github.com/argoproj/argocd-example-apps.git

  • 경로: guestbook

  • 네임스페이스: guestbook (자동 생성)

  • 동기화 정책: 자동 동기화, 자동 정리, 자동 복구

2.4 애플리케이션 상태 확인

./52_check_application.sh

문제 해결

일반적인 문제들

1. AWS 프로필 설정 문제

증상: Unknown options: --profile 오류 발생

해결방법: * env.sh 파일에서 AWS_PROFILE 변수가 올바르게 설정되어 있는지 확인 * AWS CLI 프로필이 실제로 존재하는지 확인: aws configure list-profiles

2. ArgoCD 서버 엔드포인트 문제

증상: ArgoCD Server Endpoint: None 또는 연결 실패

해결방법: * ArgoCD Capability가 ACTIVE 상태인지 확인: ./04_check_capability.sh * Capability 배포가 완료될 때까지 대기 (보통 5-10분 소요) * 대안으로 Kubernetes 서비스에서 직접 엔드포인트 확인: bash kubectl get svc -n argocd argocd-server

3. Identity Center 설정 문제

증상: Capability 생성 시 Identity Center 관련 오류

해결방법: * AWS Identity Center가 올바르게 설정되어 있는지 확인 * 사용자 이름이 03_create_argocd_capability.sh`의 `USER_NAME 변수와 일치하는지 확인 * Identity Center가 올바른 리전에 설정되어 있는지 확인

4. IAM 권한 문제

증상: 역할 생성 또는 Capability 생성 시 권한 오류

해결방법: * AWS 계정에 다음 권한이 있는지 확인: - iam:CreateRole - iam:AttachRolePolicy - iam:ListAttachedRolePolicies - eks:CreateCapability - eks:CreateAccessEntry - eks:AssociateAccessPolicy - sso-admin:ListInstances - identitystore:ListUsers

5. ArgoCD CLI 연결 문제

증상: 클러스터 등록 시 연결 오류 또는 Context 'set' undefined

해결방법: * ArgoCD CLI 버전 확인: argocd version * 올바른 로그인 명령어 사용: argocd login <server-url> --sso * kubectl 컨텍스트가 올바른 클러스터를 가리키는지 확인

6. 리전 불일치 문제

증상: ap-northeast-1 리전을 찾는 오류

해결방법: * env.sh`에서 `AWS_REGION 변수가 올바르게 설정되어 있는지 확인 * 모든 AWS 리소스가 동일한 리전에 생성되어 있는지 확인

결론

AWS EKS Capability를 사용하면 복잡한 GitOps 도구인 ArgoCD를 매우 간단하게 배포하고 관리할 수 있습니다. AWS의 관리형 서비스 장점을 활용하여 운영 부담을 줄이면서도 강력한 CI/CD 파이프라인을 구축할 수 있습니다.

최신 스크립트는 다음과 같은 개선사항을 포함합니다: * 중복 실행 방지를 통한 안정성 향상 * AWS 프로필 자동 감지 및 적용 * 상세한 에러 처리 및 사용자 안내 * ArgoCD 서버 엔드포인트 자동 감지 * EKS Access Entry를 통한 세밀한 권한 관리
